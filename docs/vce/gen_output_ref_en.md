# gen.rb-C Output Reference

This section provides a detailed explanation of the functions gen.rb outputs for C/C++.

In the following explanation, ````PROTONAME``` refers to the protocol name set in the protocol definition file.
Functions with ````sv``` in the name are for servers,
and similarly, functions with ```cli``` are for clients.

## Functions that must be defined, compiled, and linked in the application

- ```int PROTONAME_sv_sender( conn_t _c, char *data, int len ​​)```
This function sends one record.

Arguments:
~~~
conn_t _c: The function sends this connection.
char *data: A pointer to the data to send. This is the result serialized by gen.rb.
int len: The length of the data to send (in bytes).
~~~
Please return the length of the data actually sent. Returning a negative value will result in an error and the connection will be terminated.

The following is an example of sending using the send record creation function (unparser_bin16), which can send up to 65,535 bytes.
~~~
int echoproto_sv_sender( conn_t _c, char *data, int len ​​)
{
return vce_protocol_unparser_bin16( _c,data,len);
}
~~~
In this example, data serialized by gen.rb is sent to the connection without any special processing.

- ```int PROTONAME_sv_recv_error_callback( conn_t _c,int e )```
This function is called when an invalid record is received.

Arguments:
~~~
conn_t _c: Received connection
int e: Error code
~~~
Returning a negative value in return will close the connection. By defining the contents of this function, you can implement processing that does not immediately close the connection, or optional logging or error handling depending on the error content.
In the following example, the error number is displayed to standard output and the connection is immediately closed.

~~~
int echoproto_sv_recv_error_callback( conn_t _c,int e )
{
vce_errout( "cannot receive data err=%d(%s)\n", e, STRERR );
return -1;
}
~~~

- ```int PROTONAME_toolong_recv_warning( conn_t c,int proto_id,int length)```

This function is called when a record longer than the maximum length allowed by the protocol is received. An abnormally long record may indicate an attack, not just an application or VCE bug.

Arguments:
~~~
conn_t _c: Received connection<br>
int proto_id: Protocol ID<br>
int length: Received record length</p>
~~~
You can close the connection by returning a negative value.

The following example closes the connection without any special processing.
~~~
int echoproto_toolong_recv_warning( conn_t c,int proto_id,int length)
{
return -1;
}
~~~

## Application-side settings required

For the following functions, the address of the function generated by gen.rb must be notified to VCE by calling a VCE function.

- ```PROTONAME_sv_pcallback```
This is a dispatch function that parses the contents of a single record and invokes the necessary RPC.
In the following example, it is set to tcpcontext_t using the vce_tcpcontext_set_conn_parser function.
~~~
vce_tcpcontext_set_conn_parser( tcpctx,
vce_protocol_parser_bin16,
PROTONAME_sv_pcallback );
~~~

## Other generated constants, etc.

- ```PROTONAME_MAX_CONNECTION```
The maximum number of connections accepted on the server side.
- ```PROTONAME_MAX_RECV_RECORD_LENGTH```
Defines the maximum length of records received on the server side. This value is the first value calculated from the function definitions in the protocol definition file.

- ```unsigned int PROTONAME_sv_get_version(unsigned int *subv)```
Gets the version of the protocol definition file (server side).
- ```unsigned int PROTONAME_cli_get_version(unsigned int *subv)```
Gets the version of the protocol definition file (client side).
- ```VCEI64 PROTONAME_get_FUNCNAME_send_count(void)```
FUNCNAME is the name of each function. Retrieves the number of times each function has been sent.
- ```VCEI64 PROTONAME_get_FUNCNAME_recv_count(void)```
FUNCNAME is the name of each function. Retrieves the number of times each function has been received.
- ```void PROTONAME_FUNCNAME_send_debugprint(int on_off)```
Turns on/off the debug print when sending a function.
- ```void PROTONAME_FUNCNAME_recv_debugprint(int on_off)```
Turns on/off the debug print when receiving a function. The default is ON for all.
Debug output is only compiled in if the GEN_DEBUG_PRINT macro is defined.
